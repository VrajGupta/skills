# Handoff: adversarial-loop wired into coder/debugger/planner

## Scope
Generalized `adversarial-loop` from a standalone tool into the build/harden/plan
mechanism that `/coder`, `/debugger`, and `/planner` now run internally, plus
resolved a real merge conflict between this branch and `main` along the way.

## Changed paths
- `adversarial-loop/SKILL.md` — added `Mode` (`build` / `harden` / `plan`) and
  `Operating mode` (`interactive` / `pipeline`) concepts. Pipeline mode uses a
  fixed default trio (no per-run picker) and auto-picks the highest-rated
  result (no "ask the user") so it can run unattended inside a queue-draining
  pipeline stage.
- `coder/SKILL.md` — Step 2's plain `tdd` build is now `/adversarial-loop`
  (`build` mode, pipeline operating mode): orchestrator + fixed trio, each
  test-first in its own worktree, highest-rated diff wins.
- `debugger/SKILL.md` — merged the old Step 1 (four-nets audit & fix) and
  Step 2 (red-team corners) into one Step 1 that runs through
  `/adversarial-loop` (`harden` mode). Renumbered old Step 3 → Step 2 (move to
  Review Ready) and old Step 4 → Step 3 (handoff/push). The real payoff: a bug
  one participant's pass finds and another's doesn't gets surfaced in
  cross-critique and fixed in every worktree, not just cross-examined once.
- `planner/SKILL.md` — chain items 3 (`to-spec`) and 4 (`to-tickets`) merged
  into item 3, `/adversarial-loop` (`plan` mode) — competing spec + ticket
  breakdowns from the already-**grilled** decisions (grilling itself stays a
  single interactive human conversation, not parallelized) — plus item 4,
  **Publish**, which takes the winning worktree's output through the existing
  GitHub Projects / `tickets.md` publishing mechanics unchanged.
- `README.md` — pipeline detail blocks (`/planner`, `/coder`, `/debugger`),
  the model-profile table's new explanatory paragraph (fixed default trio
  priority list, why `/reviewer` stays out of this), and the
  `ticket-implementation-tdd` catalog line all updated to reflect the new
  mechanism. Also resolved a real 3-hunk merge conflict against `origin/main`
  (see below).
- `.handoff-adversarial-loop-pipeline-integration.md` — this file.

## Behavior contract
- **`/reviewer` is deliberately untouched.** It stays a single blind judge —
  running it through `/adversarial-loop` would defeat the point of an
  unreviewed-by-itself verdict.
- **Fixed default trio priority list** (pipeline mode only): `Kimi K3, GLM 5.2,
  GPT-5.6 Sol, Grok 4.5, Fable 5, Opus 5, Sonnet 5` — first 3 distinct from
  the orchestrator's own model. Interactive mode (a human running
  `/adversarial-loop` directly) still prompts via `AskUserQuestion` every run,
  unchanged from before this integration.
- **Auto-pick, not ask, in pipeline mode.** The orchestrator rates every
  participant (including its own attempt) and auto-picks the highest-rated
  result so `/coder`/`/debugger`/`/planner` can keep draining a ticket queue
  unattended. Every participant's rating — not just the winner's — is logged
  in that stage's handoff for human review after the fact.
- **`plan` mode never runs the interactive grill.** It starts only after
  `/planner`'s grill + lock-invariants steps are done; participants compete on
  turning locked decisions into a spec/tickets, not on what the decisions are.
- **`harden` mode's value is cross-pollination**, not just cross-examining one
  known fix: bugs found by one participant's audit and missed by another's get
  surfaced in relay rounds and fixed everywhere.
- Depth-1 (no participant may spawn further agents) and the CLI-shellout
  mechanism for non-Claude models are unchanged from the standalone skill.

## Merge conflict resolved
`gh pr list` showed PR #20 (`docs/readme-production-standards` → `main`) as
OPEN with the conflict GitHub reported. Root cause: this branch's local history
diverged from `origin/main` at commit `17c098e`, and `main` had already merged
equivalent-but-differently-worded `gauntlet-loop` README content via earlier
PRs (#18, #19) that this branch's own commits (`7300cc2`, `560ecd2`, `ce6fa1c`)
never saw. Result: 3 real textual conflicts in `README.md`, all the same
shape — pure additions on this branch's side with nothing on `main`'s side to
reconcile (the `adversarial-loop` catalog row, the gauntlet-loop install
snippet, and the `adversarial-loop/` layout-tree line). Resolved by keeping
this branch's content at each conflict. In-progress uncommitted work (this
pipeline-integration change) was stashed before the merge and popped back
after, so nothing from either was lost.
