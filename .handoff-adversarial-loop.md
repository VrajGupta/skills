# Handoff: adversarial-loop skill

## Scope
Added a standalone `adversarial-loop` skill: the orchestrator plus 3 user-picked
model/provider subagents each independently attempt the same coding task in
isolated git worktrees, then relay diffs and critiques hub-and-spoke round by
round until unanimous sign-off or a 6-round cap. No auto-merge — every final
diff is rated by the orchestrator and presented side by side for the user to
pick.

## Behavior contract
- Orchestrator role gate: hardcoded good/not-good model tier list in Step 0 of
  the skill (edit that block when new models ship). Good tier also attempts
  the task as a 4th participant; not-good tier stays pure orchestrator over 3.
  Unknown/unlisted models default to not-good.
- Subagent model/provider picked via `AskUserQuestion` every run — no
  hardcoded default trio.
- Claude-family picks run through the native `Agent` tool; other providers run
  through whatever headless CLI the current harness has wired to them (e.g.
  `codex exec`), checked for presence/auth before the run starts.
- Every participant, including the orchestrator's own attempt, gets its own
  isolated git worktree so final diffs are symmetric and comparable.
- Every subagent brief carries an explicit no-further-delegation line,
  matching the standing depth-1 subagent rule.
- Loop stops on unanimous `SIGN-OFF: yes`, hard-capped at 6 rounds; hitting the
  cap without unanimity is reported as open disagreement, not forced
  consensus.
- Final step never merges or auto-picks a winner: orchestrator rates every
  entry (including its own), the user chooses, and merging the chosen branch
  is left to the user.
